# Third-party notices

## Fixed-point FFT — `full-solution/src/fft64.cpp`, `student-starter/src/fft64.cpp`

The radix-2 fixed-point FFT in this project is **adapted** from the ECE4760
course material at Cornell University, which is itself a derivative of a
long-lived piece of public-domain DSP code.

**Provenance chain**

1. **Tom Roberts**, `fix_fft`, 8 November 1989 — the original fixed-point
   radix-2 decimation-in-time FFT.
2. **Malcolm Slaney** (Interval Research), 15 December 1994 — revision.
3. **Bruce R. Land**, Cornell University, ECE4760 — AVR/GCC adaptation with a
   Q8.8 inline-assembler multiply, published as course material at
   <http://people.ece.cornell.edu/land/courses/ece4760/Math/GCC644/FFT/FFTfixGCC644_macro.c>
4. **This project** — 64-point adaptation for the ATmega328P, described below.

The attribution to Roberts and Slaney is carried in the Cornell source itself
and is reproduced here and at the top of `src/fft64.cpp`.

**Changes made in this project**

| Change | Reason |
|---|---|
| 128 points → 64 points | one FFT covers exactly one 8 ms analysis frame; the working buffers cost 256 B instead of 512 B, which is 12% of the ATmega328P's entire SRAM |
| Runtime SRAM sine table → PROGMEM Q15 table | the original computes the table at boot with floating-point `sin()`, spending 256 B of SRAM and pulling in libm; the table is now generated by `tools/gen_tables.py` into flash |
| Q8.8 `multfix` inline assembler → plain C Q15 multiply | the C version compiles for the host, which is what lets the whole recognition chain be unit-tested off-target; the measured cost is 1.31 ms against an 8 ms budget, so the assembler's speed was not needed |
| `int` loop counters → `uint8_t` | 64 points needs 6 bits of index; 8-bit counters are one instruction per operation on an 8-bit core |
| Explicit overflow bounds documented | the per-stage 1/2 scaling and the `FFT_INPUT_SHIFT` pre-scale are stated with their worst-case magnitudes, so "no overflow" is checkable rather than inherited |

## Project inspiration — Speech Lock

> **Speech Lock**
> William Salcedo, Rafael Ramos, Rene Lorenzo
> ECE 4760 Final Project, Cornell University, Fall 2014
> <https://people.ece.cornell.edu/land/courses/ece4760/FinalProjects/f2014/wjs253_rrs72_ral255/speech_lock_webpage/speech_lock_webpage/webpage.html>

The idea of a voice-operated lock on an 8-bit AVR comes from this project.

**No code other than the FFT was taken from it.** Its mel filterbank, its
32-point DCT, its Linde–Buzo–Gray vector quantiser and its shifting nth-root
square root were all read and then deliberately not used, because they do not
fit in an ATmega328P's 2 KB of SRAM and because an order-free codebook is the
wrong model for a passphrase lock. The reasoning is set out in full in
[`full-solution/docs/cornell-comparison.md`](full-solution/docs/cornell-comparison.md).

The Cornell page also references three further sources that this project does
**not** use, listed here for completeness:

* fixed-point macros — <http://people.ece.cornell.edu/land/courses/ece4760/Math/GCC644/fixedPt/FixedPtOps_macro.c>
* 1-D DCT — <http://people.ece.cornell.edu/land/courses/ece4760/Math/GCC644/DCT/dct1dGCC644_macro.c>
* UART driver by Joerg Wunsch, and an LCD library under the GPL

This project's `uart.cpp` is written from scratch against the ATmega328P
datasheet and shares no code with Wunsch's driver. There is no LCD.

## Everything else

All other source, documentation, tooling and test code in this repository was
written for this project.

* **Hamming window** — `w[n] = 0.54 − 0.46·cos(2πn/(N−1))`, a standard textbook
  definition, computed by `tools/gen_tables.py`.
* **CRC-16/CCITT-FALSE** — the standard polynomial 0x1021 with initial value
  0xFFFF, implemented bitwise from the specification. The test vector
  `CRC("123456789") = 0x29B1` is the published check value for that variant.
* **Integer square root** — the classical bit-by-bit restoring algorithm.
* **`|z| ≈ max + min/4`** — the well-known "alpha max plus beta min" magnitude
  approximation.

These are standard algorithms rather than copied code; they are named here so a
reader can check them against the reference definition.

## Tooling

The Python tools use only the CPython standard library (`wave`, `array`,
`math`, `argparse`, `unittest`). No third-party Python packages are required.

The firmware is built with **avr-gcc** and **avr-libc** via **PlatformIO**, and
the cycle benchmark runs under **simavr**. None of those are vendored into this
repository; they are installed by `pio run` and
`pio pkg install -g -t tool-simavr`.
